Lecture 16: Kruskal’s Algorithm#

Warmup#

Question 28

Consider the following graph:

  1. Find a minimum spanning tree using Kruskal’s Algorithm.

  2. How might you show Kruskal’s Algo generates a spanning tree? Why minimum?

Answer

The resulting graph you should end up with is:

The question is, how do you know the resulting graph is a spanning tree? Moreover, how do you know this tree’s edge numbers sum to the minimum of all such spanning trees?

For example, the warmup example graph has more than one spanning tree (you can verify this for yourself). But, if we look at the generated tree, the edge weights of this tree sum to a number less than or equal to every other spanning tree (the trick will be proving the process generates such a tree).

Proof of “Correctness”#

We will proceed to prove the correctness of Kruskal’s Algo. By proving correctness, we show that indeed Kruskal’s Algo generates the output that it claims to generate: a minimum spanning tree.

First, recall Kruskal’s Algo:

Definition 42 (Kruskal’s Algorithm)

  • Input: A weighted, connected graph \(G=(V,E)\)

  • Body: Build a minimum spanning tree \(T\)

      1. Initialize a graph \(T\) on vertices \(V\) with \(m=0\) edges

      1. While \(m<n-1\):

        1. Remove edge with minimum weight \(e\in E\)

        1. If adding \(e\) to \(T\) creates a cycle, do not add it. Otherwise, do.

  • Output: A minimum spanning tree \(T\) of \(G\)

Proof. Let \(G=(V,E)\) be a weighted, connected graph. Let \(T\) be the output from Kruskal’s Algo. We will first show \(T\) is a spanning tree.

Spanning Tree: Since we initialize \(T\) with all of the vertices of \(G\), \(T\) is already a spanning subgraph of \(G\). By not adding edges that create cycles, \(T\) has no cycles. The only thing left to prove is that \(T\) is connected.

So, assume \(T\) is not connected. Then, there are at least two vertices \(u\) and \(v\) in \(T\) with no \(uv\)-path between them. That is, \(u\) and \(v\) are in different components of \(T\). Call the component \(u\) is in \(T_1\) and the component \(v\) is in \(T_2\).

Note that \(T_1\) and \(T_2\) must also be cycle-less. Since \(G\) is connected, there must have been edges between \(T_1\) and \(T_2\) that Kruskal’s Algo considered. The only way to create a cycle by adding one of these edges is if there were already a path between the endpoints of that edge. Since this is not the case for a vertex in \(T_1\) and a vertex in \(T_2\), Kruskal’s Algo would have added an edge between them since at some point this edge is minimum and no cycle is created.
