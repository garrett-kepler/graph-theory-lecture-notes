### Finishing up proof for Kruskal's 

Last lecture, we proved that Kruskal's algorithm produced a spanning tree. We are halfway to proving the result we want:

````{prf:theorem} Proof of Correctness for Kruskal's

Kruskal's algorithm produces a minimum weight spanning tree when connected graphs are inputted.
````

````{prf:proof}
__Spanning Tree__: See last lecture!

__Minimum Weight__: We'll use a proof by contradiction! 

Consider inputting a connected, weighted graph $G=(V,E)$ into Kruskal's algorithm and receiving a weighted spanning tree $T$. We will assume that there is some minimum spanning tree $T_1$ different than $T$ and show that $T$ and $T_1$ must be the same. 

So, let $T_1$ be a minimum weight spanning tree that shares the maximum number of shared edges with $T$ ($T\neq T_1$). So, $T$ and $T_1$ differ by at least one edge. Say $e\in E(T)$ such that $e\notin E(T_1)$. Add this edge to $T_1~$. $~T_1$ must now have a cycle. There is some edge in this cycle that is not in $T$. Say $e'\in E(T_1)$ such that $e'\notin E(T)$. Remove this edge from $T_1~$. Call this new graph with $e$ and not $e'$ $T_2~$. Note that we removed the cycle we added such that $T_2$ is also has no cycles. Moreover, removing an edge in a cycle does not disconnect a graph so $T_2$ is connected. That is, $T_2$ will be a tree and have the same edges as $T_1$ without $e'$ and with $e$ added.

Denote the sum of the weights in $T$ as $w(T)$ (likewise with every other edge set or graph). What is $w(T_2)$? Well, we have the weight of $T_1$, plus the weight of $e$, and minus the weight of $e'$. That is,

$\begin{align*}
w(T_2)=w(T_1)+w(e)-w(e')
\end{align*}$

Recall that $T$ is the output from Kruskal's algo. Kruskal's algo picks edges with minimum weight first. This means that $e$ had minimum weight out of all the edges in $G$ at some point. This means, whatever weight $e'$ had, it had to be greater than or equal to the weight of $e$. So, $w(e)\leq w(e')$. In other words, $w(e)-w(e')\leq 0$. So, we know,

$\begin{align*}
w(T_2)&=w(T_1)+w(e)-w(e')\\
&\leq w(T_1)+0=w(T_1)
\end{align*}$

Recall that $T_1$ is assumed to be a minimum spanning tree with the <it>maximum number of edges shared with $T$</it>. Note that since $T_2$ has every edge that $T_1$ shares with $T$ <u>and</u> $e$. That means $T_2$ has <u>more</u> shared edges with $T$ than $T_2$. And, since $w(T_2)\leq w(T_1)$ we have a minimum spanning tree with more shared edges than $T_1$. This contradicts the assumption that $T_1$ is the minimum spanning tree with the maximum number of shared edges. So, $T$ and $T_1$ must be the same by contradiction.
````

### Breadth-First Search

Another very useful graph algorithm is a <it>search</it> algorithm that also finds trees in graphs:

````{prf:definition} Breadth-First Search (graph)
- Input: A graph $G=(V,E)$ and a starting vertex "$root$"
- Body: Build a tree $T$
     1. Initialize a graph $T$ on vertices $V$ with no edges
     2. Label $root$ explored
     3. Let $Q=(root)$ (an ordered list).
     4. While $Q$ is not empty:
        - 4a. Remove first element $u\in Q$.
        - 4b. For each edge $\{u,v\}\in E$:
            - If $v$ is not unexplored,
                - label it explored
                - add $\{u,v\}$ to $T$ 
                - add $v$ to end of $Q$
- Output: A tree $T$ from $G$
````

````{prf:question}
When is the output from Breadth-First Search (graph) a spanning tree?
````
````{prf:answer}
When the input graph is connected!
````
